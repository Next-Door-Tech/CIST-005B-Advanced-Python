# Restaurant Operations Simulation Lab

Build a restaurant operations simulation in Python. Your program should model a restaurant processing customers and orders during one shift.

The focus of this lab is on using array lists, linked lists, stacks, and queues together in one structured program, while also practicing inheritance and polymorphism.

---

## Requirements

### 1) Simulation Scope

Your program must simulate a single restaurant shift.

During the simulation:

* Customers arrive
* Orders are created
* Orders wait to be processed
* Orders move through preparation
* Orders are completed
* The program prints a running log

The simulation ends after a fixed number of time steps.

---

### 2) Required Classes

You must use object-oriented design with inheritance.

Required:

* `Order` (base class)
* `DineInOrder` (child class)
* `TakeoutOrder` (child class)

Each order type must behave differently in a meaningful way.

---

### 3) Required Data Structures

Your program must use all four of the following:

* **Array List (Python list)**: store the menu and completed orders
* **Linked List (your own node-based implementation)**: store active kitchen orders
* **Stack (your own implementation)**: store and process prep steps for the current order
* **Queue (your own implementation)**: store waiting customer orders

Your linked list, stack, and queue must be implemented as classes.

---

### 4) Required Simulation Cycle

Each time step must do the following in order:

* Add arriving customers/orders to the queue
* Move the next waiting order from the queue into the active kitchen linked list
* Process prep steps using the stack
* Mark finished orders as complete and move them to the completed orders list
* Print a status log for that time step

---

### 5) Required Output

Your program must print:

* A step-by-step event log during the simulation
* An end-of-shift summary with:
  * total customers processed
  * total completed orders
  * dine-in order count
  * takeout order count
  * total revenue

---

### 6) Reliability

Your program must handle empty structures safely (empty queue, empty stack, empty linked list) and must not crash during normal simulation flow.

---

* **OOP Design (15%)** – Proper inheritance and polymorphism with order classes
* **Demo (50%)** – Live Demo with Oral Questions about the Data Structures used
